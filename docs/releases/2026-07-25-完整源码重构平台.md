# 2026-07-25 完整源码重构平台发布摘要

## 发布目标

本版本将项目从本地逆向 CLI 扩展为可部署的中文 Web 平台，并闭合“证据提取、知识图谱、模型补全、真实构建、错误修复、行为比较、可信放行”的完整源码重构主链路。

## 平台架构

- Go 控制面统一提供中文前端、认证权限、实验任务、SSE 事件、Provider 管理、工件浏览和 worker 调度。
- Python 分析内核负责解包、反编译、资源提取、Semantic IR、知识图谱、源码工程生成、构建修复和行为验证。
- PostgreSQL 保存任务、事件、用户、Provider 配置与用量；工作区卷保存样本、源码工程和验收工件。
- 所有分析、构建和行为 worker 在 Docker 中以 `network=none` 运行；模型请求由控制面 Provider broker 代理，API Key 不进入 worker。
- Web 工作台提供任务进度条、去重输出、工具与 Skill 分类、源码文件树、工件查看、模型配置优先级与连接测试。

## 完整重构闭环

1. 接收 EXE、DLL、APK、ELF、ZIP 等授权输入，并保留输入哈希与包内目录树。
2. 按目标类型组合现有反编译器、资源提取器和平台工具，生成带来源链的证据。
3. 建立 `BinaryTarget -> ToolStage -> EvidenceArtifact -> Module` 知识图谱。
4. 使用 OpenAI-compatible Provider 逐模块生成或修复完整源码文件，严格校验模型 JSON Schema、允许路径和证据引用。
5. 生成 CMake 等工程结构、项目清单和依赖锁，并在隔离容器内真实编译。
6. 编译失败时提取有界诊断，将错误反馈给模型，应用修复后重新构建；无效修改会被拒绝。
7. 通过真实子进程比较退出码、stdout、stderr 和输出文件；行为不匹配时进入模型修复循环。
8. 只有结构、依赖、构建、行为和网络隔离门禁全部通过，API 才设置 `complete_buildable=true`。

## 模型服务

- 当前生产模型配置为 `gpt-5.6-terra`。
- 支持多个模型按优先级排序，以及多个 API Key 按槽位顺序故障转移。
- Provider 配置页可直接测试当前未保存表单，显示实际模型、密钥槽位与回退次数。
- 不再部署或使用 7B/Ollama 本地兜底模型；全部外部凭据不可用时任务明确失败。
- 明文密钥只存在本机或服务器受限配置文件，不进入 Git、Docker 构建上下文、报告或前端响应。

## 自动构建与部署

`build-deploy-aliyun.yml` 在 `main` 分支更新后执行：

1. Python、Go 和前端测试。
2. 构建生产 Docker 镜像。
3. 将镜像压缩为发布包并保存为 Actions artifact。
4. 通过专用 SSH 部署密钥上传至阿里云。
5. 在服务器加载镜像，通过 Compose 更新 Web 与 PostgreSQL。
6. 验证容器健康状态及 `https://pe.toporeduce.cn/readyz`。

服务器只负责加载已经构建的镜像，适配 2 核 2G 配置。Nginx 提供 TLS、64 MiB 上传限制和长任务/SSE 反向代理。

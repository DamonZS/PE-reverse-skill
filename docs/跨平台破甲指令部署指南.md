# 跨平台破甲指令部署指南

> 让同一份破甲指令（激活词 `拓扑` / `AC`，统一拓扑身份）在 **Codex / Claude / Cursor(Trea) / WorkBuddy** 四类平台上都能生效。
>
> 核心原则：**指令内容平台无关，注入机制平台相关。**

---

## 1. 整体架构

| 层 | 作用 | 实现 |
|----|------|------|
| 内容层 | 破甲指令核心（身份设定、激活词、行为规则） | `load_instruction_bundle("topo-ac-unrestricted")` 复用原子弹 |
| 适配层 | 按平台注入指令 | `reverse_analyzer/instructions/platforms/*` |
| 验证层 | 双轨识别（拓扑版 + Leila 版） | 复用 `codex/inspect.py` 检测逻辑 |

```
破甲指令内容库（平台无关）
   ├── Codex     → config.toml  model_instructions_file
   ├── Claude    → settings.json  UserPromptSubmit hook stdout 注入
   ├── Cursor    → .cursor/rules/*.mdc  alwaysApply:true
   ├── WorkBuddy → topo-ac-unrestricted skill 触发逻辑
   └── (Trea = Cursor 别名)
验证检测器（平台无关，双轨识别）
```

---

## 2. 平台注入机制（为什么不同）

| 平台 | 注入位置 | 生效原理 |
|------|----------|----------|
| **Codex** | `~/.codex/config.toml` → `model_instructions_file = "./gpt5.5-unrestricted.md"` | Codex 全局指令文件接管（已成熟） |
| **Claude** | `~/.claude/settings.json` → `hooks.UserPromptSubmit` → 脚本 stdout | 退出码 0 时 stdout 作为上下文注入给 Claude；`CLAUDE.md` 兜底 |
| **Cursor** | `.cursor/rules/topo.ac.mdc` → `alwaysApply: true` | 始终包含在模型上下文开头，最契合 model_instructions_file 语义 |
| **WorkBuddy** | `topo-ac-unrestricted` skill（触发词 `拓扑`/`AC`） | WorkBuddy 是云端 agent，**无法接管 system prompt**，唯一正路是 skill 触发逻辑 |

> ⚠️ WorkBuddy 无法通过本机文件改写 agent 的 system prompt。在 WorkBuddy 中发「拓扑」是否触发，取决于**是否安装了对应 skill**。这也是安装流程区别于其他三平台的原因。

---

## 3. 安全模型

与现有 `codex` 子包完全一致：

- `--allowed`（或 `--force`）才放行写入，绝不自动发现/走查目标。
- 所有写入：路径 confine + 原子写（temp + rename）+ backup + 可逆。
- `--dry-run` 零副作用预览，**无需 `--allowed`**。
- 只操作调用者显式指定/授权的目录。

## 4. 使用方法

### 4.1 查看平台与别名

```bash
reverse-instruct list
```

```
platforms: codex, claude, cursor, workbuddy
aliases:   trea→cursor, claude-code→claude, codex-cli→codex, ...
```

### 4.2 查看将部署什么（只读预览，不写文件）

```bash
# 查看某个平台默认会写哪些文件
reverse-instruct describe --platform claude
reverse-instruct describe --platform cursor
```

### 4.3 检测目标当前状态（只读）

```bash
reverse-instruct inspect --platform codex
reverse-instruct inspect --platform claude
reverse-instruct inspect --platform cursor
reverse-instruct inspect --platform workbuddy
```

### 4.4 实际部署（需确认授权）

```bash
# Codex（复用现有成熟后端）
reverse-instruct deploy --platform codex --allowed

# Claude
reverse-instruct deploy --platform claude --allowed

# Cursor（默认写入 ~/.cursor；也可指定项目目录）
reverse-instruct deploy --platform cursor --target <项目目录> --allowed

# WorkBuddy（生成 skill 包到 ~/.workbuddy/skills）
reverse-instruct deploy --platform workbuddy --allowed
```

### 4.5 只预览不写入（无需授权）

```bash
reverse-instruct deploy --platform claude --dry-run
```

## 5. 各平台验证要点

部署后用 `inspect` 确认破甲信号已注入：

| 平台 | 验证点 |
|------|--------|
| Codex | `model_instructions_file` 指向 gpt5.5-unrestricted.md；含 `拓扑`/`AC` markers |
| Claude | settings.json 含 `UserPromptSubmit` hook；`instruction.md`（根层）含 `拓扑`，hook 脚本位于 `hooks/instruction-inject.sh` |
| Cursor | `.cursor/rules/topo.ac.mdc` 含 `alwaysApply: true` + `拓扑` |
| WorkBuddy | `~/.workbuddy/skills/topo-ac-unrestricted/SKILL.md` 含触发词 `拓扑` |

---

## 6. 后续可扩展项

- **Claude / Cursor / WorkBuddy 的 `restore`** 尚未接持久化 evidence manifest（当前依赖 `.backup/` 快照），可补全。
- **WorkBuddy skill 安装自动化**：当前生成 skill 包后需在 WorkBuddy 端手动导入（custom skill / marketplace）。
- **检测器跨平台统一**：可将双轨识别（拓扑+Leila）抽成平台无关的共用检测模块，供四个平台 inspect 复用。

# Intelligent Reverse Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the checked-in PE skill workbench into a single, non-executing router that starts with a master skill and selects workflows from intent, local artifacts, endpoint descriptors, interface types, package ecosystems, and protection-review requests.

**Architecture:** `reverse_analyzer.skills.runtime.SkillRouter` remains the only decision module. `routing.json` declares route matching, workflow stages, subskills, tool IDs, capability candidates, and authorization gates; `SkillCatalog` enriches the resulting plan with `SKILL.md`, scripts, and references. The router categorizes URLs without fetching them and never invokes providers, scripts, or tools.

**Tech Stack:** Python 3.10+, stdlib JSON/dataclasses/urllib parsing, unittest, existing repository skill assets.

## Task 2: Implement the Deep Router Module

**Files:**

- [ ] **Step 1: Add structured input and route metadata**

Add `RouteInput`, `ToolRecord`, and the following `RouteRule` fields:

```python

workflow: tuple[str, ...]
subskills: tuple[str, ...]

```

Keep `route(query, *, target=None, endpoint=None, interface=None, package=None, limit=3)` and `route_by_id(...)` as the only public planning seams.

- [ ] **Step 2: Parse endpoint descriptors without network access**

Use `urllib.parse.urlsplit` only to validate an absolute `http` or `https` URL and lower-case its host/path for matching. Preserve `_local_target_text()` rejection of URI values passed to `target`.

- [ ] **Step 3: Score every configured input dimension deterministically**

Use priority as the tie-breaker base and add independent points for matched intent keywords, file extensions, input kinds, interface tokens, package tokens, and URL descriptors. Sort with `(-score, skill_id)` so ties remain stable.

- [ ] **Step 4: Resolve tool IDs and validate asset references**

Load `config/tool-manifest.json` once. Reject a route that names a tool absent from the manifest, a workflow/subskill with no local `SKILL.md`, or a declared master skill file outside the suite root. Return manifest records in `workflow.tools`; do not import or call a provider.

- [ ] **Step 5: Build master-first plans**

Return this shape from both `route()` and `route_by_id()`:

```python
{
    "status": "planned",
    "input": {"query": "...", "target": None, "endpoint": "...", "kinds": ["url-descriptor"]},
    "master_skill": {"id": "master", "path": "SKILL.md", "title": "..."},
    "workflow": {"master": {...}, "stages": [...], "subskills": [...], "tools": [...]},
    "authorization_required": False,
    "primary": {...},
    "secondary": [],
}
```

For `risk_level == "controlled"`, add an authorization gate and a boundary stating that the plan does not bypass, modify, inject into, or execute a target.

- [ ] **Step 6: Enrich plans in `SkillCatalog.route()`**

Resolve the master, every stage, and every subskill through the existing `SkillRecord` reader, adding a `skill` record when a checked-in document is present. Retain the existing `primary["skill"]` compatibility field.

- [ ] **Step 7: Run the Task 1 tests and verify they pass**

Run: `python -m unittest tests.test_skill_runtime.SkillRuntimeTests.test_url_descriptor_routes_without_network_access tests.test_skill_runtime.SkillRuntimeTests.test_package_and_protection_routes_include_workflow_and_gate -v`
